The format of a file is detected by its signature, not by its extension. Internally the
package has one driver per format (`LibraryReaderInterface`), and the facade picks the first
driver that recognises the file, in this order: ELF, PE, Mach-O. If none does, the
constructor throws `UnsupportedFormatException`.

Everything described on the [library info](../library-info/), [exports](../exports/) and
[imports](../imports/) pages is common to all formats. Each format also exposes extra data
through subclasses of the base classes, which you can reach with `instanceof`:

```php
use FFI\Reflection\ReflectionLibrary;
use FFI\Reflection\ReflectionLibrary\Reader\ELF\ElfReflectionExportSymbol;

$library = new ReflectionLibrary('libsqlitejdbc.so');

$symbol = $library->getSymbol('JNI_OnLoad');

if ($symbol instanceof ElfReflectionExportSymbol) {
    echo $symbol->getType()?->name . ' ' . $symbol->getSize() . ' ' . $symbol->getIndex() . "\n";
}

// Func 1638 111
```

Rely on this extra data only when you really need it. It describes the internals of a
particular format, and the common API is the one meant to be stable.

## Comparison

| | ELF | PE | Mach-O |
|---|---|---|---|
| Typical files | `*.so` | `*.dll`, `*.exe` | `*.dylib`, `*.bundle` |
| Byte order | Recorded in the header | Always little-endian | Recorded in the header |
| Exports from | Dynamic symbol table | Export directory | Export trie, or the symbol table of a stripped image |
| Imports from | Needed libraries and versioned undefined symbols | Import and delay-load directories | Dylib load commands and undefined symbols |
| Symbols of an import | Only versioned ones | All | All |
| Optional imports | Never (symbols can be) | Delay-loaded DLLs | Weak dylibs |
| Symbol versions | Yes | No | No |
| Forwarders | No | Yes | Re-exports |
| Calling convention | `Default` | Recovered for 32-bit images | `Default` |
| Nameless symbols | No | Yes, by ordinal | No |

Detailed pages: [ELF](./elf/), [PE](./pe/), [Mach-O](./macho/).

## Not supported

A universal ("fat") Mach-O archive, which holds several images in one file, is not read:
the constructor throws `UnsupportedFormatException`. Extract the slice you need first
(for example with `lipo -thin`).

A file that is neither of the three formats, such as a static archive (`*.a`) or a script,
is rejected with the same exception.
