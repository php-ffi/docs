`ffi/reflection-library` reads a shared library from disk, without loading it, and tells
what is inside: the architecture it is built for, the symbols it exports and the
libraries (with their symbols) it imports. Everything you need to know before writing an
[`FFI::cdef()`](https://www.php.net/manual/en/ffi.cdef.php) declaration against it.

It understands the three binary formats of the major platforms: ELF (`*.so`), PE
(`*.dll`, `*.exe`) and Mach-O (`*.dylib`). The format is detected from the contents of the
file, not from its extension, and you can read a Linux library on Windows or the other way
around.

## Installation

```bash
composer require --dev ffi/reflection-library
```

Requires PHP 8.4 or later. The package does not need `ext-ffi`: it only reads bytes.

<Aside type="note">
The package is meant to be a development tool (IDE helpers, checks, code generation), hence
`--dev`. Nothing prevents you from using it at runtime.
</Aside>

## Quick start

`FFI\Reflection\ReflectionLibrary` is the only entry point. Pass it a path or a library
name:

```php
use FFI\Reflection\ReflectionLibrary;

$library = new ReflectionLibrary('kernel32.dll');

echo $library->getFileName() . "\n";
echo $library->getBits() . ' bit, ' . $library->getArchitecture()?->name . "\n";
echo count($library->getImports()) . ' imports, ' . count($library->getSymbols()) . " symbols\n";

var_dump($library->hasSymbol('CreateFileW'));

// C:\Windows\System32\kernel32.dll
// 64 bit, Amd64
// 107 imports, 1698 symbols
// bool(true)
```

The numbers depend on the build of Windows.

<Aside type="note" title="Examples on this site">
Most examples use the `sqlitejdbc` binaries from the tests of the package (one build per
platform and architecture) and refer to them by bare file name, for example
`libsqlitejdbc.so`. The outputs were taken from those files and from system DLLs of
Windows.
</Aside>

## Finding the library

The constructor accepts the same thing as `FFI::cdef()`: either a path to an existing file
or a library name. A name is resolved to a file by
[`ffi/location`](/utils/location/), which searches the directories the operating system
loader searches, so `new ReflectionLibrary('kernel32.dll')` finds the system file and
`getFileName()` returns its absolute pathname.

If the name resolves to nothing, the constructor throws
`LibraryNotFoundException`. See [Errors](./errors/).

## What the object gives you

| Page | What it covers |
|---|---|
| [Library info](./library-info/) | Address size, endianness, architecture and kind of the file. |
| [Exports](./exports/) | Symbols the library offers: names, addresses, forwarders, calling conventions. |
| [Imports](./imports/) | Libraries the file depends on and the symbols it takes from each. |
| [Formats](./formats/) | What is specific to ELF, PE and Mach-O. |
| [Dumping](./dumping/) | Casting a library to a string. |
| [Errors](./errors/) | The exceptions and when they are thrown. |

The file is read lazily. The constructor only resolves the name, opens the file and checks
that its format is supported. The headers are parsed on the first call of `getBits()`,
`getArchitecture()` and the like, and the tables of imports and exports on the first call
of `getImports()` or `getSymbols()`. The result is cached in the object. This means that a
corrupted file is reported by the call that needs the broken part, not necessarily by the
constructor.
