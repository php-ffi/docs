`ffi/reflection-library` reads a shared library from disk, without
loading it, and tells what is inside: the architecture it is built for,
the symbols it exports and the libraries it imports. This is what you
need to know before writing an
[`FFI::cdef()`](https://www.php.net/manual/en/ffi.cdef.php) declaration.

It reads ELF (`*.so`), PE (`*.dll`, `*.exe`) and Mach-O (`*.dylib`)
files. The format is detected from the contents, so you can read a Linux
library on Windows and the other way around.

## Installation

```bash
composer require ffi/reflection-library
```

Requires PHP 8.4 or later. The package does not need `ext-ffi`: it only
reads bytes.

## Quick start

```php
use FFI\Reflection\ReflectionLibrary;

$library = new ReflectionLibrary('kernel32.dll');

echo $library->getFileName() . "\n";
echo $library->getBits() . ' bit, '
    . $library->getArchitecture()?->name . "\n";
echo count($library->getImports()) . ' imports, '
    . count($library->getSymbols()) . " symbols\n";

var_dump($library->hasSymbol('CreateFileW'));

// C:\Windows\System32\kernel32.dll
// 64 bit, Amd64
// 107 imports, 1698 symbols
// bool(true)
```

The counts depend on the build of Windows. Other examples in this
section use the `sqlitejdbc` binaries from the tests of the package
(`libsqlitejdbc.so`, `sqlitejdbc.dll`, `libsqlitejdbc.dylib`) and system
DLLs.

## Finding the library

The constructor takes what `FFI::cdef()` takes: a path to a file or a
library name. A name is resolved to a file by
[`ffi/location`](/utils/location/), which searches where the operating
system loader searches. `getFileName()` returns the absolute pathname.
If the name resolves to nothing, the constructor throws
`LibraryNotFoundException`.

The file is read lazily: the constructor checks the format only, headers
and tables are parsed on the first call that needs them and cached. A
corrupted file is therefore reported by that call, not by the
constructor.
