The parser reads C23 and the extensions of GCC, Clang, MSVC and PHP FFI that
real headers use, see [Presets](../presets/). What follows is not supported.

- **The preprocessor.** Macros and `#include` are not processed, give the
  parser [preprocessed source](/preprocessor/with-parser/).
- **Function bodies.** The body of a definition and of a GCC statement
  expression `({ ... })` is not parsed, the tree keeps its text.
- **Keyword spellings outside reserved names:** `asm` after a declarator,
  `_cdecl`, `cdecl`, `_inline`, `_declspec`.
- **`$` in identifiers:** `int a$b;`.
- **Raw string literals:** `R"(abc)"`.
- **Obsolete syntax:** `{[1] 5}` and `{ y: 1 }` designators, old-style
  (K&R) function definitions.
- **Extended `asm`** at the file scope: `__asm__("nop" : );`.
- **Clang:** block literals (`^{ ... }`), `_ExtInt`, `__private_extern__`,
  `__arm_streaming`, `_Countof` with a type name.
- **GCC:** named address spaces (`__seg_fs`).
- **MSVC:** implicit `int`, `__declspec` with a string (SAL annotations),
  `__extension__` and qualifiers in any place of a declaration.
- **Declarations that declare nothing:** `const;`, `struct S { int; };`.
- **Bugs of PHP FFI's own grammar:** incomplete escape sequences
  (`"\x"`), empty character constants, `{=1}` initializers, initializers
  of functions, `#` as a comment in the middle of a line.
- **A line splice inside a token** other than a literal. The preprocessor
  removes it.

Some of the extensions that the parser does accept read differently in other
compilers, for example `"\e"` (MSVC reads `e`), block pointers or the octal
prefix `0o17`. The set accepted depends on the [preset](../presets/). The
full list with examples is in the README of the package.
