The list returned by `Parser::parse()` holds nodes that implement `RootDeclarationInterface`.
They live in `FFI\Parser\Node\Declaration`.

| Class | Source | Notable properties |
|---|---|---|
| `VariableDeclaration` | `extern const char *names[16];` | `name`, `type`, `initializer` |
| `FunctionDeclaration` | `int printf(const char *, ...);` | `name`, `type` (a `FunctionType`) |
| `FunctionDefinition` | `int f(int x) { return x; }` | `name`, `type`, `body` |
| `TypeDefDeclaration` | `typedef void (*callback_t)(int);` | `name`, `type` |
| `TagDeclaration` | `struct S { int a; };`, `enum E;` | `type` (`RecordType` or `EnumType`) |
| `TypeDeclaration` | `int;`, `const struct S;` | `type` |
| `StaticAssertDeclaration` | `static_assert(1, "ok");` | `condition`, `message` |
| `AttributeDeclaration` | `[[deprecated]];` | `attributes` |
| `AsmDeclaration` | `__asm__("nop");` | `instructions` |

```php
use FFI\Parser\Parser;

$header = <<<'C'
typedef unsigned int u32;
int counter = 5;
int sum(int a, int b);
struct S { int a; };
static_assert(1, "ok");
static inline int id(int x) { return x; }
C;

foreach (new Parser()->parse($header) as $declaration) {
    echo new ReflectionClass($declaration)->getShortName() . "\n";
}

// TypeDefDeclaration
// VariableDeclaration
// FunctionDeclaration
// TagDeclaration
// StaticAssertDeclaration
// FunctionDefinition
```

## Declarators

`VariableDeclaration`, `FunctionDeclaration`, `FunctionDefinition` and `TypeDefDeclaration` extend
`DeclaratorDeclaration`: they declare a name. All four have

| Property | Type | Meaning |
|---|---|---|
| `name` | `Identifier` | The declared name, read it as `$declaration->name->value`. |
| `type` | `?TypeInterface` | The type built of the specifiers and the declarator, see [Types](../types/). |
| `specifiers` | `?SpecifierList` | Storage-class and function specifiers, alignment and attributes written before the type. `null` if none, see [Specifiers](../specifiers/). |
| `attributes` | `?AttributeList` | Attributes after the declared name and the GCC ones around the declarator. |
| `asmLabel` | `?AsmLabel` | The symbol name, `__asm__("_f")` in `int f(void) __asm__("_f");`. |
| `initializer` | `?InitializerInterface` | The value after `=`. |

The kind of the node follows from the type, not from the keyword: `typedef` gives a
`TypeDefDeclaration`, a function type gives a `FunctionDeclaration`, anything else is a
`VariableDeclaration`. A function whose type comes from a typedef name (`F f;`) is a
`VariableDeclaration` too.

Each declarator is a node of its own, and the nodes of one declaration share the type of the
specifiers:

```php
use FFI\Parser\Parser;

foreach (new Parser()->parse('int a, *b, c[2];') as $declaration) {
    echo $declaration->name->value . ' ' . new ReflectionClass($declaration->type)->getShortName() . "\n";
}

// a IntType
// b PointerType
// c SizedArrayType
```

### Functions

The `type` of a `FunctionDeclaration` is a `FunctionType`: it holds the return type and the
parameters. A `FunctionDefinition` adds the `body`.

The body is not parsed. `FunctionBody::$raw` is the text of the compound statement exactly as
written, braces included.

```php
use FFI\Parser\Parser;
use FFI\Parser\Node\Specifier\StorageClassSpecifier\StaticSpecifier;

$function = new Parser()->parse('static inline int id(int x) { return x; }')[0];

echo $function->body->raw . "\n";
var_dump($function->specifiers->first() instanceof StaticSpecifier);

// { return x; }
// bool(true)
```

### Typedefs

`TypeDefDeclaration::$type` is the type the name stands for. The `typedef` keyword itself is
the `TypeDefSpecifier` in `specifiers`.

```php
use FFI\Parser\Parser;

$typedef = new Parser()->parse('typedef void (*callback_t)(int);')[0];

echo $typedef->name->value . ' ' . $typedef->type::class . "\n";
echo $typedef->specifiers[0]::class . "\n";

// callback_t FFI\Parser\Node\Type\PointerType
// FFI\Parser\Node\Specifier\StorageClassSpecifier\TypeDefSpecifier
```

### Assembler labels

```php
use FFI\Parser\Parser;

$function = new Parser()->parse('int f(void) __asm__("_f");')[0];

echo $function->asmLabel->name->value . "\n";

// _f
```

`AsmLabel::$name` is a `StringLiteral` or a `ConcatenatedStringExpression`. Labels and
`AsmDeclaration` are extensions of GCC, a [preset](../../presets/) without the features
`AsmLabels` and `AsmDeclarations` rejects them.

## Declarations without declarators

- `TagDeclaration` is a structure, union or enumeration declared by itself: `struct S { int a; };`
  or `struct S;`. Its `type` is a `RecordType` (`StructType`, `UnionType`) or an `EnumType`.
  The tag declared together with a declarator, as in `struct S { int a; } x;`, is not a
  separate declaration: it is the `type` of `x`.
- `TypeDeclaration` has only specifiers: `int;`, `const struct S;`.

Both have the `specifiers` of the declaration.

## Other root declarations

- `StaticAssertDeclaration` has the `condition`, an expression, and the `message`, a
  `StringLiteral` or a `ConcatenatedStringExpression`, or `null` if omitted. It is also the
  member of a structure, see [Types](../types/#structures-and-unions).
- `AttributeDeclaration` is a declaration of attributes alone, `[[deprecated]];`. Its
  `attributes` list is empty only for `[[]];`.
- `AsmDeclaration` is a basic assembler statement at the file scope, `__asm__("nop");`.
  Its `instructions` is a `StringLiteral` or a `ConcatenatedStringExpression`.

## Declarations inside types

Some declarations live inside types and do not appear at the root of the file:
`MemberDeclaration` (a member of a structure or union), `Parameter` (a parameter of a function type)
and `Enumerator`. They are described on the [Types](../types/) page.
