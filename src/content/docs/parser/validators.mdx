The grammar accepts some code that C forbids, because the constraint is easier to check on the
finished tree than in the grammar: `long float x;`, `int f(void)(void);`, `struct S { int a[]; int b; };`.
**Validators** check such constraints. `Parser::parse()` runs them after the
[transformers](../transformers/), as a separate walk over the final tree, and `Parser::validate()` does
not.

```php
use FFI\Parser\Exception\ValidationException;
use FFI\Parser\Parser;

try {
    new Parser()->parse("int a;\nlong float x;");
} catch (ValidationException $e) {
    echo $e->getMessage() . ' (offset ' . $e->offset . ")\n";
}

// Invalid combination of type specifiers `long float` (offset 7)
```

A validator rejects only what the tree shows. A type behind a typedef name is not resolved, and
the rules accept C23 only, so an extension that lifts a constraint has a rule of its own, which
the [preset](../presets/) removes when it accepts the extension.

The constraints that leave the tree well-formed are not checked and are up to the consumer of the
tree: lvalues, constant expressions, places of specifiers and attributes, widths of `_FloatN`,
universal character names.

## Built-in rules

All rules live in `FFI\Parser\Validator\Rule` and are listed by `Validator::getDefaultRules()`.

| Rule | Rejects |
|---|---|
| `TypeSpecifierRule` | An invalid multiset of type specifiers: `long float`, `unsigned double`, `long long long`. |
| `TypeInferenceRule` | A missing type specifier outside a declaration with an inferred type: `static x = 1;`, `const *p;`, `sizeof(const)`. `auto x = 1;` is valid. |
| `StorageClassSpecifierRule` | An invalid combination of storage-class specifiers: `typedef static int T;`, `static extern int x;`. |
| `AtomicTypeRule` | An array, function, atomic or qualified type in `_Atomic(...)`: `_Atomic(int[3])`. |
| `StructTypeRule` | A flexible array member that is not the last member of a structure. |
| `MemberDeclarationRule` | A member without a declarator that is not an anonymous structure or union, a member of a function type or of the type `void`: `struct S { int; };`. |
| `BitFieldRule` | A bit-field of a non-integer type: `float x : 3;`. |
| `EnumTypeRule` | An underlying type of an enumeration that is not an integer type, is an enumeration or is bit-precise: `enum E : float { A }`. |
| `ArrayDeclaratorRule` | An array of functions or of `void`: `void a[3]`. |
| `FunctionDeclaratorRule` | A function that returns a function or an array: `int f(void)(void)`. |
| `FunctionDefinitionRule` | A definition that does not declare a function, or has a named `void` parameter: `int x {}`, `int f(void x) {}`. |
| `InitializerRule` | An initializer of a function or a typedef: `int f(void) = 0;`. |

### Extension rules

These rules are in `FFI\Parser\Validator\Rule\Extension`. Each one is the constraint of C23 that
a compiler lifts and that [a feature of the preset](../presets/#features) removes.

| Rule | Rejects | Removed by the feature |
|---|---|---|
| `ComplexIntegerTypeRule` | `_Complex` applied to a non-floating type: `_Complex int` | `ComplexIntegers` |
| `ModifiedTypedefNameRule` | A typedef name together with a type modifier: `unsigned T` | `ModifiedTypedefNames` |
| `GnuFlexibleArrayMemberRule` | A flexible array member in a union or as the only member of a structure | `GnuFlexibleArrayMembers` |
| `TaggedAnonymousMemberRule` | A member without a declarator that is a tagged structure or a typedef name: `struct S { struct T; };` | `TaggedAnonymousMembers` |
| `AlignOfExpressionRule` | An expression as the operand of `alignof` | `AlignOfExpressions` |
| `BuiltinTypeArgumentRule` | A type name among the arguments of a `__builtin_` function | `BuiltinTypeArguments` |
| `GenericTypeOperandRule` | A type name as the controlling operand of `_Generic` | `GenericTypeOperand` |

## Violations

Every rule returns `FFI\Parser\Validator\Violation` objects, read-only: the `message`, the `offset`
of the fragment and its `length` in bytes, or `null` if unknown.

The parser collects the violations of all rules, sorts them by offset and throws one
`ValidationException`, see [Errors](../errors/#validation-errors): its message is the first
violation (with "(and N more)" if there are more), `offset` and `length` point to it, and
`violations` holds all of them.

```php
use FFI\Parser\Exception\ValidationException;
use FFI\Parser\Parser;

try {
    new Parser()->parse("long float a;\nint b[3](void);");
} catch (ValidationException $e) {
    echo $e->getMessage() . "\n";

    foreach ($e->violations as $violation) {
        echo $violation->offset . ': ' . $violation->message . "\n";
    }
}

// Invalid combination of type specifiers `long float` (and 1 more)
// 0: Invalid combination of type specifiers `long float`
// 19: Element type of an array should not be a function
```

## Standalone use

`FFI\Parser\Validator` works without the parser. `new Validator($rules)` takes the rules,
`Validator::createDefault()` creates one with the default rules, and `validate()` takes a
`list<RootDeclarationInterface>` and returns a `list<Violation>` sorted by offset, empty if the
tree is valid.

```php
use FFI\Parser\Parser;
use FFI\Parser\Validator;

$declarations = new Parser(validatorRules: [])->parse('long float x;');

foreach (Validator::createDefault()->validate($declarations) as $violation) {
    echo $violation->message . "\n";
}

// Invalid combination of type specifiers `long float`
```

## Writing a rule

A rule implements `FFI\Parser\Validator\ValidatorRuleInterface`:

| Method | Meaning |
|---|---|
| `getNodeClasses(): iterable` | The classes or interfaces of the nodes the rule checks. |
| `validate(NodeInterface $node, ValidationContext $context): iterable` | The `Violation` objects, empty when the node is fine. A generator works. |

`ValidationContext` has the `parents` and `declarations` of the [traverser context](../traverser/#context).

```php
use FFI\Parser\Exception\ValidationException;
use FFI\Parser\Node\Declaration\SpecifiedDeclaration\DeclaratorDeclaration\FunctionDeclaration;
use FFI\Parser\Node\NodeInterface;
use FFI\Parser\Parser;
use FFI\Parser\Validator;
use FFI\Parser\Validator\ValidationContext;
use FFI\Parser\Validator\ValidatorRuleInterface;
use FFI\Parser\Validator\Violation;

final class NoLeadingUnderscore implements ValidatorRuleInterface
{
    public function getNodeClasses(): iterable
    {
        yield FunctionDeclaration::class;
    }

    public function validate(NodeInterface $node, ValidationContext $context): iterable
    {
        if (str_starts_with($node->name->value, '_')) {
            yield new Violation(
                message: 'The name "' . $node->name->value . '" is reserved',
                offset: $node->name->offset,
                length: strlen($node->name->value),
            );
        }
    }
}

$parser = new Parser(validatorRules: Validator::getDefaultRules([new NoLeadingUnderscore()]));

try {
    $parser->parse("int _a(void);\nint ok(void);\nint _b(void);");
} catch (ValidationException $e) {
    echo $e->getMessage() . "\n";
}

// The name "_a" is reserved (and 1 more)
```

<Aside type="caution">
`validatorRules: [new NoLeadingUnderscore()]` replaces the default rules. To extend them pass
`Validator::getDefaultRules([...])`, it returns the default rules followed by yours. To turn the
validation off pass `validatorRules: []`: the tree is then built without the checks, as in the
[standalone](#standalone-use) example.
</Aside>
